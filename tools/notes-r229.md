# CarDesk 4306 / 1.0.1210-system

## 这一版修了什么

### 1. 单画模式下音乐卡片「内容不跟卡片走」
分隔条一拖，右侧音乐卡就会变窄，但卡片里的版式是按 520 宽摆的绝对坐标，
于是出现：进度条右端顶到卡片边框、时间数字贴边、封面和歌名挤在一起、
控制键被裁掉一半。

现在音乐卡按**自己的实际宽度**分三档重排：

| 档 | 卡片宽度 | 版式 |
|---|---|---|
| 宽 | ≥ 460 | 设计板版式（封面 96、歌名从 140 起、收藏 / 播放模式都在） |
| 中 | ≥ 320 | 封面缩到 72、歌名从 112 起、收起收藏 / 播放模式两个图标按钮 |
| 窄 | < 320 | 隐去封面，歌名从 24 的留白起、占满整行；控制键左右间距收紧到 12，不再被裁 |

另外，进度条 / 时间行 / 歌名 / 歌手 / 歌词 / 来源行这些整行元素统一补了
**右边距 24**，任何宽度下都不会再贴边（原来只有左边距）。

### 2. 拖动调比例时的卡顿（第229轮）
拖动时卡宽每帧都在变，原来每帧都会 `resize` 一次画中画的虚拟屏，
承载应用（比如高德）每帧都要重新排版重画整张地图，主线程被它拖住，
拖动只有 10 fps 左右、连手指的 move 事件都被合并。

现在拖动期间**不 resize 虚拟屏**，只把目标尺寸记下来，松手那一帧再一次性 resize；
镜像（窗口内渲染）和 ActivityView 两条路线都改了。

## 怎么用
不需要任何设置，自动生效。

## 细节
- 音乐卡三档的判定在 `NavPage.applyCombinedWidth()`，宽度变化时自动套用；
- 拖动预览在 `PipSurface.beginDragPreview()/endDragPreview()` 与
  `PipMirrorHost.beginDragPreview()/endDragPreview()`；
- 拖动结束会记一条「画中画拖动结束」日志（含步数），方便车上排障。

## 验证
- 全量单测 **2644 / 0 failures**；
- 模拟器（cardesk28，API 28）：
  - 音乐卡宽度 525 / 363 / 218 三档分别截图确认：进度条与时间行左右都有留白、
    控制键在 218 宽下完整可见、封面在窄档自动隐去；
  - 全屏进入 / 还原：地图铺满整幅 1920 宽，右侧无空白，还原后画面还在；
- 车机上的拖动流畅度这一版仍需要实车确认（模拟器是软件渲染，帧率不代表 820A）。
