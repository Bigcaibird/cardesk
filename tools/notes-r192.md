Dock 按 112 走（对齐系统导航预留带）+ 图标整体放大

一、Dock 与系统导航预留带对齐（原来差 8px）
- 之前系统给所有 App 让出的底部预留带是 112px（RRO 覆盖 framework-res 的 navigation_bar_height），但 CarDesk 的 Dock 只有 104 高 —— 中间那 8px 是「系统留了位、却没人画」的缝，而且诊断判据带 4px 容差，一直没报出来。
- 现在 Dock 本体做成 112 贴底：预留带、Dock 占位、Dock 绘制高度三个数字改成相等，桌面 Dock 顶边 976 → 968。
- 实测（API 28 模拟器 dumpsys window）：系统导航栏与 CarDesk 全局 Dock 窗口的 frame 完全重合，都是 [0,968][1920,1080]；别的 App 的可用区（mAppBounds）正好停在 968。

二、图标整体放大约 8%（跟 104 → 112 同一比例）
- 导航键槽 60 → 64、键底板圆角 20 → 22、房子图标 13 → 15、应用宫格 7×7 → 8×8、分屏图标 ±14 → ±16、360 徽标 ±24×±15 → ±26×±16。
- 快捷应用格 76 → 82；媒体卡高 88 → 96、封面 60 → 64、播放键 44 → 48、上下曲 40 → 44。
- 空调图标槽 48 → 52、风扇 100×70 → 106×76。
- 间隙一律不动 —— Dock 宽 1920 是死的，挤出来的宽度由中间的媒体卡让出（歌名区 236 → 220px，仍放得下）。

三、校验
- 单测 2283 → 2291 项全绿（新增 DockHeightAlignmentTest 8 项，钉死「Dock 高度 == 预留带高度」这个不变量）。
- 模拟器实拍：桌面 Dock 顶边 968、底边 1080；导航页内容底边 940，从未被挡；叠在别的 App 上时预留带被完整填满、无空隙。
