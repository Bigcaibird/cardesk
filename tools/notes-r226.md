# CarDesk 4303 / 1.0.1207-system

## 这一版修了什么

**视频壁纸不再掉帧，同时画中画的圆角 / 切页残留 / 高德错乱都保住了。**

上一版为了保圆角，把视频壁纸的画法换成了 `TextureView`（每帧都要 GPU 合成一次全屏画面），
车机上就卡了。这一版把视频换回**省电的 `SurfaceView` 硬件图层直通**，
但画中画改走一条新路：**自己建虚拟屏，把承载画面画进桌面窗口里**（`TextureView` 镜像）。

为什么这样能两头都顾上：

- 视频走硬件图层 → 图层贴在窗口**下方**，窗口必须半透明才能透出视频 —— 这是省电的前提；
- 但窗口一透明，画中画原来的画法（`ActivityView` 里那块独立图层）就不受窗口轮廓裁剪了：
  圆角变直角、画面与窗口坐标错位（用户看到的「高德错乱/右侧裁切」）、切到首页还留一块黑卡；
- 新路让画中画回到**窗口自己的缓冲**里画 —— 它就是个普通 View，圆角、隐藏、裁剪全部按 View 规则走。
  而它只有画中画那么大（约 1287×867），合成的代价远小于全屏视频。

## 怎么用

- 什么都不用改：视频壁纸开（`design_video_wallpaper=1`）+ 后端保持 `0`（`SurfaceView`）即可。
- 用 `TextureView` 后端（`design_video_wallpaper_backend=1`）时仍走原来的画中画画法，行为不变。
- 关掉视频壁纸时窗口不透明，也走原来的画法，行为不变。

## 细节

- 新增 `core/PipRenderPlan.kt`（纯逻辑：窗口透明 ⇒ 镜像路线）、`ui/pip/PipMirrorHost.kt`（自建虚拟屏 + `TextureView` 宿主）。
- 虚拟屏尺寸变化只 `resize`、**不重建**（重建会把承载应用 task 推到主屏 = 上一轮修过的那个症状）。
- 新虚拟屏的 displayId 会登记进 `ActivityEmbed`，上一轮的**搬移守护窗口**与黑屏自愈照常工作。
- 释放时先注销登记再释放虚拟屏；原来的 `ActivityView` 路线一行没动。

## 验证

- 单测 **2628 / 0 失败**（新增 3 条渲染路线判据）。
- 模拟器（cardesk28 / API 28）实测，视频壁纸走 `SurfaceView` 后端：
  - 高德配成画中画 → 画面嵌在卡里、四角**圆角**、视频壁纸正常播放；
  - 首页 ⇄ 导航页来回切 → 首页无黑块、回来画面**静止子区域逐字节相同**（整卡差异 0.294%，来自高德自己的地图动画）、高德 `START` 新增 **0** 次、`FATAL` **0** 条。
- 详细过程见 `emu-verify/REPORT-r226.md`。
