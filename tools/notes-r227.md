# CarDesk 4304 / 1.0.1208-system

## 这一版修了什么

**第225/226轮验收查出来的三个问题，全部修掉；另外补上了「画中画切全屏」这条路径的两个洞。**

### 1. 视频壁纸的默认渲染后端改回省电那条路（SurfaceView）

上一版（4303）的更新说明写的是「视频壁纸开 + 后端**保持 `0`（SurfaceView）**即可」，
但代码里的**默认值**其实还是 `TextureView` ⇒ **默认配置走的一直是掉帧那条路**，
你报的「**现在的默认方案**掉帧很严重」这件事，在默认配置下**并没有被修**。

这一版把默认值改回 `SurfaceView`（HWC 硬件直通、不掉帧），**不需要你做任何操作**，
视频壁纸开着就是省电那条路。

### 2. 开机后视频壁纸不再「跳回开头」重播一遍

画中画那条「自建虚拟屏」路线建虚拟屏时，系统会给那块虚拟屏下一份**配置覆盖**
（`ActivityManager: Override config changes=… for displayId=NN`），
连带把**我们自己的窗口 surface** 重建一次
（系统侧可见 `BufferQueueProducer: [SurfaceView - …] detachBuffer`）。

`SurfaceView` 的 surface 跟着窗口走 ⇒ surface 被换 ⇒ 旧播放器作废。
以前的新播放器**从第一帧开始** ⇒ 用户看到「开机后视频跳回开头」。

这一版在 surface 被换掉时**记下当前播放位置**，重建后 `seekTo` 回去 ⇒ **视频接着播**。

（顺带把窗口 format 改成**建窗之前就定好**，`SurfaceView` 那条路不再需要中途改 format。）

> 顺带说明：试过「同一个播放器 `setSurface` 换输出面」——
> 实测在模拟器上**画面会黑**（解码器没有真的换输出面），那条路作废。

### 3. 画中画切全屏 / 还原（窗口内渲染路线）

上一版新加的「窗口内渲染」路线（自建虚拟屏 + `TextureView` 镜像）有两个洞：

- **切一次全屏画面就黑了**：进/出全屏时承载面会被搬一次家
  ⇒ `TextureView` 的 `SurfaceTexture` 销毁重建
  ⇒ 虚拟屏一直指着**已销毁**的旧 surface。
  这一版在新的 `SurfaceTexture` 到位时，把虚拟屏**重新指过去**（不重建虚拟屏 ——
  重建会把承载应用推到主屏）。
- **全屏 ↔ 还原之后画面不重排**：这一版原来靠「重新发一次启动」让应用按新尺寸重排，
  但镜像路线的承载面是 `TextureView`，它**没有** `startActivity` ⇒ 旧代码**根本没重新拉起**。
  这一版改成由镜像宿主自己发（它知道自己的虚拟屏 id）。

## 怎么用

- **什么都不用改**：视频壁纸开着就行（默认走省电的 `SurfaceView`）。
- 画中画配高德：照旧在「设置 → 画中画」里选高德，
  首页 ⇄ 导航页切来切去、点画中画卡左缘进全屏再点还原，都正常。

## 细节

- 默认后端改回 `SurfaceView`（`core/Prefs.kt`），更新说明与代码口径**一字不差**。
- 窗口 format 只有一个来源（`core/VideoWallpaper.targetWindowFormat`），
  且在**建窗之前**算出来（`MainActivity.applyWindowFormatBeforeCreate`）。
- 「窗口透明性」与「画中画路线」两条判据**共用同一个函数**
  （`needsTranslucentWindow`），口径不一致就是「直角 / 错位 / 切页残留黑卡」那三个老毛病。

## 验证

- 单测 **2637 / 0 失败**（新增 9 条：默认值、窗口 format 目标值、两条口径一致性）。
- 模拟器（cardesk28 / API 28）实测：
  - **默认配置**（`design_video_wallpaper_backend` 这个键**根本不存在**）
    → 走 `SurfaceView` + 窗口内渲染路线，高德嵌在画中画里、四角圆角；
  - 首页 ⇄ 导航页来回切 → 首页无黑块、切回高德 `START` 新增 **0** 次、`FATAL` **0** 条；
  - **画中画 → 全屏 → 还原**：画面正常、不黑。
    还原时承载应用会按新尺寸**重发一次启动**（`by=resize`）——这是让应用重新布局的**设计内行为**，
    不是崩溃、也不是跑到主屏（高德始终待在虚拟屏上）。
- 详细过程见 `emu-verify/REPORT-r227.md`。
