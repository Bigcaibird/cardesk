# 第138轮 验证报告

> 主题：① 第二页音乐卡的媒体来源补上对应 App 图标（与首页同一套方案）；
> ② 状态栏的信号 / WiFi / 蓝牙 / 热点图标按**真实状态**显示（参考工程 UNI 的口径）。
>
> 需求原文（用户）：
> 一、现在第二页的音乐播放器的媒体来源还是没有显示对应 app 的图标，同步一下首页音乐卡片的图标显示方案；
> 二、桌面状态栏的图标显示如信号，wifi，蓝牙，热点等不太准确，参考一下 UNI 的逻辑，优化 cardesk 的状态栏图标显示。

| 项 | 值 |

## 二、需求一 · 第二页媒体来源图标

| 证据 | 结论 |
|---|---|
| `y138-02-navpage-source-icon.png` | 第二页音乐卡来源行显示**真 QQ音乐 App 图标**（白底黄音符方块），不再是粉色品牌小圆点 |
| `y138-03-home-music-icon.png` | 首页音乐卡的来源图标与第二页**是同一个位图**（同一套图标方案、同一个缓存） |

### 走查时抓到的真 bug

第一版把图标 View 写成了**局部变量**：

```kotlin
val sourceIconView = MediaSourceIconView(context).apply { … }   // 局部变量遮蔽了字段
```

字段 `private lateinit var sourceIconView` 因此**从未初始化**，
`::sourceIconView.isInitialized` 恒为 false ——
`sourceId` / `sourceIcon` / `sourceLabel` 三处赋值全被跳过，
图标恒定停在默认的「通用音乐」粉色音符（**文案却是「QQ音乐」**，品牌色对不上）。

**一眼看出来的原因**：粉色 = `MediaSources.brandColor` 的兜底色（`0xFFEC4899`），
说明传进去的**文案不是**「QQ音乐」→ 来源 id / 文案根本没送到图标 View。

修正：改成**字段赋值**（`sourceIconView = MediaSourceIconView(context).apply { … }`），
模拟器复验通过。

> 这条 bug 已写进反向验证脚本的**反向 8**（把它改回局部变量 → 断言必红）。

### 脚本自身的复核（修掉了三条假绿）

第一版接线断言用「某行里出现这段文本」判断，结果这些改法**骗过去了**：

| 骗法 | 为什么骗过去了 |
|---|---|
| 改坏调用点，但**函数定义处**还有同名文本 | 断言只认文本在不在，不认是不是调用点 |
| 把调用**注释掉** | 只挡了「行尾注释」，挡不住整行注释 |
| 把赋值改成 `if (false) …` | 文本还在，逻辑已经废了 |

而且基线一度**误红**：源码注释里写着「不能写 `val sourceIconView = …`」，
纯文本检查把这段**说明**当成了代码。

修法：接线断言改成**精确文本（含缩进）+ 先剥掉行注释**再比对，
钉在**调用点**（例如 `\n        startSystemStatusSampling()\n`）而不是同名函数上；
反向 5 / 6 的锚点补上上下文，避免同一段文本在文件里出现两次导致 patch 失败。

## 六、已知限制

- **真车还没验**：车机 4G 几格信号、WiFi 已连接时的分档、蓝牙已连接时的强调色，
  这三段模拟器上走不到（无 TBox / WiFi 没连 / 无蓝牙适配器），必须真车复验。
- **热点的判断依赖隐藏 API**（`WifiManager.isWifiApEnabled`）：
  system 变体有 hidden API 白名单；普通安装包读不到时按「没开」处理，不误报。
- **状态栏图标会随状态增减**，不是固定位置：
  连了 WiFi 就不画蜂窝、热点开着就不画 WiFi ——「位置/天气」那一段会跟着让位。
  这是规则的必然结果（参考工程同样是动态的）。
- **蓝牙适配器取不到**时打一条限频告警（60 秒一条），
  用来区分「蓝牙没开」和「根本没读到蓝牙」。
- **没有发 GitHub Release、没有传 R2**（等明确指示）。
