■ 需求一 · 设置页整理（原来太乱）
- 原来「布局与显示」里的导航项写着「仪表歌词」，点进去大半却是**桌面歌词**的东西；
  仪表歌词真正的入口藏在页面**最底部**的「打开布局参数对话框…」里，
  而且对话框里桌面/仪表歌词字号混在一列里，分不清哪个调哪个。
- 现在拆成三页：
  · **桌面歌词**：导航栏歌词槽字号 + 首页中央歌词布局 / 预览 / 字号缩放
  · **仪表歌词**：投射开关 / 投射目标屏列表 / 投射状态 / 面板位置与样式 / 歌词颜色
  · **车辆信息**：胎压字号 / 车模编号 / 车辆数据源
- **彻底删除**「布局参数对话框」这个类（DesktopLayoutDialog，净删 475 行）——
  不留第三处入口，避免同一批设置三处可改。
- 顺带修掉一个旧 bug：对话框里「选中屏」的标签用的是深底深字的色，看不清。

■ 需求二 · 仪表歌词颜色联动日夜模式
- 问题量化：旧配色（照着夜间仪表调的）到了日间白色仪表底上，
  主色对比度只有 **1.52 : 1**、副色 **2.16 : 1** —— 连 WCAG AA 大字标准（3 : 1）都不到，
  这就是「日间模式下不明显」的确切数值。
- 现在日夜各一套配色（cluster/ClusterLyricColors.kt，纯 Kotlin 可单测）：
  · 夜间（仪表深底）：主 #7FE3D4 / 副 #9FB4BB → 对比度 12.45 : 1 / 8.74 : 1
  · 日间（仪表白底）：主 #0C5F57 / 副 #46535C → 对比度 **7.53 : 1** / 7.92 : 1
- **底板颜色也跟着翻**（夜间深底配亮字、日间浅底配深字）——
  不翻的话日间会变成「深字压深底板」，一样糊。
- **用户手挑的颜色优先于**日夜联动，可一键「恢复跟随日夜」；
  设置页把当前实际色值写出来（「跟随日夜 · #7FE3D4」）。
- 修掉一个隐藏的根因：投射服务原先直接读桌面主题的 `Skin.isNight`，
  而开机广播会**独立**把服务拉起来，那时桌面还没跑过、该值停在默认「夜间」，
  于是白天白底仪表上照投浅青字 —— 跟反馈的现象完全一致。
  现在日夜判定抽成 core/NightResolver.kt，桌面与投射服务共用同一份判定，不会劈叉。
