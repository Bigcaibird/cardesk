## 一、结论先行

**心形从「贴着播放键」挪到了「歌名和播放键中间」，两边都留出了明显空档。**

| | 第208轮 | 第210轮 |
| --- | --- | --- |
| 位置 | 播放键左边，**间隙 6**（看着像连成一块） | **歌名与播放键之间居中** |
| 定位方式 | 相对播放键固定偏移 | **按歌名实际宽度居中** —— 歌名越长，心形越往左 |
| 尺寸 | 52 × 52（不变） | 52 × 52（不变） |

---

## 二、几何

```
可摆区间 = [歌名右缘 + 8, 播放键左缘 − 6]      ← 两端都是最小间隙
心形     = 在这个区间里居中
竖直方向 = 与播放键同一条水平中线
```

实现要点（`ui/pages/ScenePage.kt` 的 `drawMusicCard()`）：

| 步骤 | 做法 |
| --- | --- |
| 量文字 | 先按**自然上限**（让到进度环外侧）截断并量宽 → `textEdge`（歌名/歌手取宽的那个） |
| 定位 | `leftBound = textEdge + 8`、`rightBound = 播放键左缘 − 6`，心形在两者之间**居中** |
| 兜底 | 歌名特别长、空间不够 → 心形**贴着播放键**放，绝不压到字上 |
| 文本列 | 右边界 = `min(自然上限, 心形左边缘 − 8)` —— 歌名不会从心形底下穿过去 |
| 取宽 | 用 `Paint.measureText` 量**最终绘制**的字符串宽度（长歌名被截断后右缘要跟着缩） |

## 四、单测怎么锁住这个版式（含变异检查）

`MediaActionButtonsLayoutTest` 新增两个用例：

1. **`首页音乐卡收藏按钮摆在歌名和播放键中间`** ——
   心形在歌名右缘与播放键左缘**之间**、**不贴着播放键**（间距 > 半边长）、
   且大致在两者**中间**（±15%）。
2. **`歌名极长时收藏按钮不压到歌名上`** ——
   歌名极长时文本列要让位，心形不能压到歌名上。

两个用例都做了**变异检查**（把实现改回错误版本，测试必须红）：

| 变异 | 结果 |
| --- | --- |
| 心形改回「贴着播放键」 | ✅ 用例 1 **FAILED** |
| 文本列不再为心形让位 | ✅ 用例 2 **FAILED** |

### ⚠️ 踩到的坑：Robolectric 的 `measureText` 每个字只算 1px

真机 `Paint.measureText` 返回真实字宽，**Robolectric 每个字只算 1px**。
所以「歌名极长」那个用例一开始用 26 字中文标题**抓不住**变异 ——
必须用 `repeat(200)` 这种超长标题，才够宽把文本列撑满、逼出截断分支。

⇒ 结论：**版式断言必须在真机上再验一遍**，单测只能证明「逻辑分支没走错」。
本轮两边都做了（截图里的像素就是按真机字宽算出来的）。
