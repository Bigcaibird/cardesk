  老版本「切屏后」截图与「全屏」截图逐像素一致
  → 复现真机「点了 22 次切屏、一个像素都没变」。
  截图：emu-verify/y167/y167-06~09-*.png

  对照实验（老版本 4250 退出全屏）：
    全屏态下点 chevron → 零日志 + 画面变化率 0.0000
    原因：embedtest 的 Activity 窗口被系统提升成 display 0 的 1920×1080
          全屏窗（stackId 压在桌面栈之上），把 CarDesk 画的 chevron 盖住了。
    → 属 API 28 模拟器 + embedtest 的特有现象，与本轮改动无关。

================================================================================
四、脚本踩过的坑（复跑时注意）
================================================================================

  1. 「切页」日志里 animate 夹在 from/to 和 fullscreen 之间，
     断言必须用正则 `切页 from=1 to=1.*fullscreen=false`，子串匹配不上。
  2. C 场景里 force-stop embedtest 后，CarDesk 的「黑屏自愈」会把 embedtest
     按 PiP 卡片尺寸重拉起来 → 绿像素不会归零，要看的是绿区**包围盒**。
  3. 每个场景前 restart_app 清状态；logcat -c 会清历史，
     判据要在清日志**之后**再打点。
  4. API 28 上不能用高德当画中画承载应用：它不支持副屏，
     会被系统搬到主显示器全屏、抢走桌面并吞掉点击。
