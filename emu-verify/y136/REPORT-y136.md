## 三、需求二 · 续航卡

### 三档配色

| 续航 | 档位 | 截图 | 卡片显示 |
|---|---|---|---|
| 386 km | 常态（>100） | `y136-05-range-normal-386km.png` | `386 km` **白色**（Skin.TEXT） |

| 45 km | 红（r ≤ 50） | `y136-04-range-red-45km.png` | `45 km` **红**（Skin.DANGER） |

### 剩余油量升数

卡片底部文案：`燃料剩余 · 34.3 L · 62%`

- 算式：**升数 = 油量百分比 × 油箱容量（升）**；
- 模拟器上百分比 62%、容量 55.26 L（真车实测值），62% × 55.26 = **34.26 → 34.3 L**，与截图一致；
- **不是**把原始容量值直接 ÷1000（原始值有两种形态：55263 = 55.26 L，但也可能是 55.263 这类已经换算好的数，
  直接除会静默得到 0 L）—— 转换规则集中在 `CarSignalMath.capacityLiters()`；
- 容量读不到时**不显示升数**（显示 `--`），不显示假的「0 L」。

脚本自身也复核过：

- `patch()` 的锚点必须**匹配且唯一**（`count == 1`），匹配不到/匹配多处直接**退出**，杜绝「patch 没生效 → 断言照样绿」；
- 接线断言用 `has_call()` —— 只认**代码部分**，把调用注释掉不算通过；
- 第 10/11 项断言**钉在调用点**（`rangeValueColor(range)` / `fitText(fuelSummaryText(...))`），
  而不是「函数存在就算过」。

## 六、已知限制

- **真车还没验**：模拟器的车门状态是造出来的。真车上的读数可靠性（`BodyState.doors` 会不会偶发读空）
  与剩余油量升数的精度，取决于 `INFO_FUEL_CAPACITY`（这台车实测 55263）能否稳定读到。
- **读不到就不提示**：车门状态读不到（null）时**不弹窗**，宁可晚点提醒也不误报 —— 这是刻意的取舍。
- **弹窗与 Dock 的避让按默认 Dock 高度算**（1080 屏上 Dock 从 y≈960 起，面板底边 910）；
  「增强导航栏」模式下 Dock 更高，这条**尚未在该模式下验证**。
- **只算门 / 引擎盖 / 后备箱**：车窗开不提示（车窗开是正常状态）。
- 「全关 → 弹窗自动关闭」这一条在模拟器上验证的是**「全关不弹窗」**；
  「开着 → 弹窗中 → 变全关 → 弹窗自动消失」的**中途跃迁**由代码路径与单测覆盖
  （模拟器的门状态是编译期常量，运行中改不了）。
- **没有发 GitHub Release、没有传 R2**（等明确指示）。
