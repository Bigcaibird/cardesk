第221轮：修掉第220轮验收发现的两个 P1 缺陷（诊断包导出丢日志 + 512KB 日志轮换失效）。

1）诊断包不再「整包跳过」
   上一版导出诊断时按「从最老的文件开始凑空间，凑不满就整个跳过」。
   实车上日志目录里最大的单个文件已超过包体上限，
   结果这个文件被**整个跳过**，「最近的日志」反而一份都拿不到。
   现在改成：装不下时取该文件的**尾部**（对齐行边界，先丢掉半行），
   保证「最近的日志」永远拿得到；包体大小不变。
   设备实测（2.1MB 日志）：最老的文件被裁到尾部 171KB，
   包内首行/末行都是完整行，且当前会话完整在包里。

2）512KB 日志轮换恢复
   第220轮把落盘改成「后台写线程 + 文件常驻句柄」后，
   轮换判断漏了——写满 512KB 也不换文件，单个日志一路涨到 781KB。
   现在每写一行前检查累计字节数，到 512KB 就关句柄、换新文件。
   （已用设备上的文件首行时间戳确认：该文件确实是第220轮包写的，属本轮引入的回归。）

3）截断文案的单位（第221轮收尾时自己测出来的）
   尾部保留量常常不足 1MB（包体上限 2MB 会被前面几个整文件先占掉大半），
   旧写法按 MB 取整会打印成「已只保留最后 0 MB」——看的人只会以为什么都没保留。
   现在不足 1MB 按 KB 打印（实测显示「最后 171 KB」）。

4）顺手修的
   - 磁盘剩余空间取不到时（availableBytes <= 0）不再误判成「空间不足」而停止落盘，
     真写不进去仍走 ENOSPC 降级。
   - 设置页的日志预览不再打 NOTE_MARK 标记（原实现把日志原文当成文案做了标记完整性校验，
     日志里出现敏感词会误报）。

5）效果（同口径翻页 A/B，cardesk28 模拟器）
   - jank 比例：旧包中位 6.38% → 新包中位 1.08%
   - Missed Vsync：两包全程 0
   - 最长帧：两包均 ≤ 32ms
